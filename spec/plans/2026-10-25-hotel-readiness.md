# 酒店目录与入口完善实施计划

用户已明确要求调整湖景、测试已连接模型、完善常规物资和风险处理，并说明每次入住刷新及存储方案；WiFi 身份入口仅作为落地 idea。本计划按已有平台和权限边界执行。

1. 记录真实模型的有限合成对话，先复现口语解析、设施答复和风险优先级差异。
2. 为目录/服务三态、口语与风险、并发库存添加失败回归；保留旧用例。
3. 统一目录元数据，接入只读查询与当前会话的待核验服务记录，修复语言/风险边界。
4. 空状态使用更大湖景，活动状态保持紧凑；浏览器核查两种断点与单一输入区。
5. 完成 docs/stay_data_and_operations.md，更新主规格/验收/追溯链接；说明现有本地界面各自持有运行时，多住客共享事实须使用 API 部署模式。
6. 焦点回归、云端复测、一次独立代码复核、完整离线验收，保存真实证据后提交。

命令使用 `.venv/Scripts/python.exe -B -X utf8`。离线完整验证通过 `scripts/verify_release.py --output-dir <新目录>`；真实模型仅用合成住客和独立内存业务数据，不读取或重置用户已有会话。不打印 API Key，不停止用户 PyCharm 的服务。
