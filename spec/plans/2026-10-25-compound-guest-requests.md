**Spec:** [逐项住客需求](../compound_guest_requests.md)。沿用已授权的当前 checkout，使用 Superpowers 排错、TDD 和独立分工；截图只留本地。

## 文件与任务

1. 主代理：`guest_requests.py` 负责可审计的子请求分解与设备能力判定；`hotel_core.py` 负责合并答复、原话、房号补槽、催送、称呼和范围外话术；`agent_runtime.py` 保持控制目标的数量继承。新增 `tests/test_compound_requests.py`，先 RED 再实现。
2. 语言子代理：只改 `agent_protocol.py` 与 `tests/test_language_modifiers.py`；修复“那送”“点水”等修饰误作 SKU，保留未知商品、热水/漏水及取消边界。与主代理不同时改同一文件。
3. 主代理：更新旧原子性规格/测试的版本说明及精确断言，保留原测试 ID；新增映射、受控取消/重启测试、一次有限供应商回放、独立复核后完整统一验证。
4. 集成：公开验收证据、提交代码文档、远端 CI；不发布任何新截图、不改用户 8501 服务。

## 验收与取舍

- 优先支持明确分隔的独立子请求；无法可靠拆分或数量共享的表达仍澄清，不为了看似流畅而猜测。
- 默认单件数量显式出现在答复，未知目录不伪造为“酒店已确认没有”；房内设备未接 API 不声称执行。
- 拆解复用既有部门提案与监督校验，禁止绕过 runtime 在循环里直接扣全局库存。
- 旧测试断言的改变由用户此次“水可送、泡面不提供也逐项答复”的明确要求驱动；记录旧版本和新边界，不能静默放松成“任意部分成功都算通过”。
