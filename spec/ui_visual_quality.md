# AegisStay 界面视觉与酒店空间仿真规格

本文件是当前版本的界面验收规格，覆盖主题对比度、住客入口、房态地图、物资卡片和酒店空间仿真。它补充主规格中的业务要求；旧的 [UI 交互专题](ui_and_interaction_spec.md) 与 [早期房态规划](hotel_simulation_spec.md) 只保留为历史背景，不能作为本版本的通过证据。

## 1. 目标与边界

工作台服务一所学校的单酒店。界面要让住客先对话，让值班人员一眼看懂房态、工单和物资；空间仿真只用于运营定位和演示当前合成 PMS 状态，不声称是建筑施工图，也不替代真实 PMS 或消防图纸。

## 2. 当前交付契约

### UI-01 主题和对比度

1. `日间`、`护眼`、`夜间` 三套主题必须通过同一组 CSS 变量驱动背景、卡片、正文、辅助文字、边框和主色。
2. 每套主题的正常正文和辅助文字相对页面背景的 WCAG 2.1 对比度均不低于 **4.5:1**；主按钮文字与主按钮背景不低于 **4.5:1**。大字号标题最低 **3:1**。
3. 侧栏标题、说明、单选项、折叠面板和禁用按钮必须显式继承主题颜色，不能出现深色背景配深色字或白色按钮配近白字。禁用只降低操作能力，不降低可读性。
4. 占位文字、Tab 未选中/选中状态、错误/成功提示和房态图例也必须使用主题变量或有明确对比度的固定颜色。

### UI-02 住客客户端双页签

1. 首页客户端区域只有两个并列页签：`💬 住客对话` 和 `🧠 会话黑板`。
2. 可见消息输入框只出现 **1 个**，位于住客对话页签顶部；黑板页签展示 L1 短期窗口、L2 工作上下文、住客档案和 L4 工单总线摘要。
3. 黑板页签不能直接输出调试 JSON；详细 Trace 以可折叠表格查看。保留隐藏的兼容输入只为 AppTest，不得成为第二个可见输入框。
4. 首屏加载后无需向下滚动即可看到对话标题、输入框和发送按钮；发送后必须 `st.rerun()`，当前轮消息立即出现在消息区。

### UI-03 房态矩阵

1. 桌面端每层固定 **6 列**，每个房间卡片尺寸一致；筛选后不足 6 个房间时用无交互的虚线占位格补齐末行。
2. 小屏（视口宽度不超过 800px）切换为 3 列，不能产生横向滚动；卡片悬停或键盘聚焦显示房号、房态、住客、库存、退房和工单数。
3. 房态颜色必须同时有文字和图例，不得仅靠颜色区分：在住、空净房、待清洁、维修中四种状态都必须可读。

### UI-04 物资卡片

物资按布草、客耗、借用设备、餐饮分组，以卡片展示数量、单位、库存健康度和进行中预留；不得把原始 Python 字典或 JSON 作为主要运营界面。库存为 0、低库存和充足三种状态必须有文字标签。

### UI-05 酒店空间仿真

运营中枢在房态矩阵之前展示当前选中楼层的简易平面图，至少包含：

- 左右两侧客房区，房间号与当前 PMS 房态同步；
- 两部电梯、一个安全楼梯和一个布草/服务核心；
- 建筑照片或稳定的占位背景、楼层标题和四种房态图例；
- 悬停房间能看到房态，存在处理中工单时显示工单提示。

仿真图不写入业务状态，不新增第二份房态数据；切换楼层或筛选条件后，图和矩阵读取同一个 `pms_rooms` 快照。

## 3. 可复现实验与量化判定

### ENV-UI

```powershell
$py = (Resolve-Path '.venv\Scripts\python.exe').Path
& $py -B -X utf8 -m unittest -v tests.test_visual_contract tests.test_streamlit
```

机器判定必须同时满足：

| 检查 | 门槛 | 失败判定 |
| --- | --- | --- |
| 主题颜色 | 3 套主题各自 `text/bg >= 4.5`、`muted/bg >= 4.5`、`accent_text/accent >= 4.5` | 任一主题或任一字段低于门槛 |
| 页面结构 | 客户端页签恰含“住客对话”和“会话黑板”；可见 composer 只有 1 个 | 出现旧的独立住客页签、两个可见输入框或页签文案缺失 |
| 房态布局 | 源码包含 `repeat(6, minmax(0, 1fr))`、占位格标记和小屏 3 列 | 自动列数、缺少占位格或小屏横向溢出 |
| 空间仿真 | 同一渲染路径含 `.hotel-sim-shell`、房间、电梯、楼梯、服务核心 | 只显示数字/JSON，或仿真状态不来自 PMS |
| 回归 | `tests.test_visual_contract` 与 `tests.test_streamlit` 零失败、零错误、零跳过 | 只看 HTTP 200、截图或进程退出码，不读取 unittest 结果 |

人工复核至少截取三张图：护眼首页首屏、夜间首页首屏、运营中枢房态与仿真图；截图不得包含 API Key、真实住客资料或调试 JSON。截图是布局证据，不能替代颜色计算和自动测试。

## 4. 交付和边界

代码实现位于 `app.py`；颜色门槛由 `tests/test_visual_contract.py` 计算。界面通过不等于真实学校酒店现场验收，真实 PMS、SSO、建筑尺寸、消防设施和现场无障碍仍按 FIELD 方案单独验证。
