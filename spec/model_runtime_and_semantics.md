# 模型切换、连接状态与语义理解

本次目标：切换 Key/Model 后实际生效、状态可查、失败有原因、减少重复调用，并让模型提供结构化语义提案。沿用已有授权、库存、取消与原子提交机制；不更换部署框架。

## MR-01 模型连接与切换

- 有客户端对象只表示已配置，不能标成在线。区分未验证、正在测试、模型实测成功、最近调用失败/规则降级、离线。
- 连接按钮显示正在测试目标模型；GET /models 与一次短 JSON 推理均通过才算实测成功。失败显示 HTTP 状态、超时或格式错误及耗时，不显示密钥或原始异常正文。
- 本地设置成功后存入被忽略的 config.json；失败恢复旧设置。切换模型保留原会话、工单、库存和归档；有运行中任务时明确请先完成/取消，防止旧 worker 覆盖新模型。
- 侧栏独立刷新，显示当前目标、最近一次推理结果/耗时及是否规则处理；未调用云端的回合不冒充模型成功。

## MR-02 延迟与调用次数

- 在硅基流动 Qwen3 系列的业务理解/短答中使用经实测支持的 enable_thinking=false；旧 Qwen2.5 和其他服务商不无条件携带此参数。SDK extra_body 与 HTTP 顶层字段正确适配。
- 结构化理解最多输出 512 tokens，保留现有 12 秒超时与零隐式重试。错误可观测，不能静默返回空值后继续显示在线。
- 复合需求一次外层理解；已经校验的子请求复用结果，不再逐项调用理解模型。闲聊复用首轮 JSON 合规短答；首轮失败或没有合规短答时本地回复，不再重复请求生成。已知原单催送和全部取消零模型调用；复合夹带设施/故障不走单项快速路径。

## MR-03 模型语义提案与程序校验

- 在原 intent/room/sentiment 外增加 actions，每项含 kind、原话中可定位的 source。允许模型把未带标点的多项需求分开；程序验证来源、数量、目录、操作类型和覆盖情况后才执行。无效/遗漏提案退回现有解析，不执行猜测物品或修改权限。
- 新别称无法核验时可澄清，不能为了语义流畅把红牛替换成矿泉水。安全探询、授权、取消代际、库存和设备能力仍由程序执行约束。
- 高优先级投诉沿用主控路由，不被不完整的模型分项覆盖；“送两瓶水，卫生太差”必须保留送水与高优先级投诉两项。
- “叫我梁老板”保存本次会话的称呼偏好，支持重启恢复；不更改登记姓名、房间、stay_id 或角色。消息可用偏好称呼，“我是谁”仍依据已绑定事实说明身份。
- 称呼与送物同句均处理，包含无标点“叫我梁老板顺便送两瓶水”；“别叫我梁老板”清除称呼偏好，权限不变。

## 验收

1. 无连接证明时不得显示在线；401、429、超时、无效 JSON 四类可见并保持密钥脱敏。
2. 换模型后会话/工单/库存/历史不变，失败不改变旧客户端；运行中切换拒绝且旧任务能正常完成。
3. 合成两项送物的模型路径恰 1 次理解调用，实际 SKU、数量和库存正确；错误模型动作不产生越权/额外工单。
4. Key 只用于用户指定的硅基流动接口，原始记录忽略且脱敏。真实 Qwen/Qwen3.5-27B 有限测试记录请求结果和耗时，不用少量案例推导总体准确率或 SLA。
5. 保留原始 127 项与固定 H01–H20，运行项目统一验收；文档解释 runtime harness 与 evaluation harness，并指出当前实际组件。

## 可复现实验

在无真实数据库的 academic 合成环境执行 `tests.test_model_runtime` 与 `tests.test_semantic_intents`。先模拟模型响应或故障，再断言实际客户端、调用次数、工单、库存与身份字段；不只判断回复文本。HTTP 401/429、超时和格式错误不得把密钥或异常正文写出。

Streamlit AppTest 从原运行时开始，先建合成订单，再点击连接按钮：连接成功后 rerun，运行时和会话仍为原对象、完整历史与业务快照相等、成功回执仍可见。Event 阻塞部门任务时切模型必须抛 RuntimeBusy，解除后原任务正常完成。配置写入失败也须还原客户端与环境。

真实模型检查只向用户指定供应商发送少量合成原句，保存逐轮耗时、调用结果、错误码、库存与最终源码哈希。超时也保留，不能从一次成功断言持续在线；不将本地快速分支算成模型成功。统一离线验收覆盖全部原有要求，证据写入新的 `.artifacts/verification/` 目录。
