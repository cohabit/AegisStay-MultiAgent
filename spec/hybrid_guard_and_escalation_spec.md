# AegisStay 大模型语义裁决、状态机安全护栏与压测 Spec

> 适用范围：历史专题设计／说明，保留当时描述，不作为当前发布规范或已实现能力证明。当前要求见 [主规格](specification.md)、[验收标准](acceptance_criteria.md)；适用范围见 [历史索引](legacy_specs.md)。

## 1. 架构目标与设计原则

在真实的智慧酒店落地场景中，纯正则穷举无法穷尽住客复杂的口误、反讽和复合情绪；而纯自主大模型又存在格式发散、不可控越权与幻觉风险。
本项目确立 **【大模型语义裁决 + 状态机合规沙盒】** 的双轨架构体系：
1. **大模型语义脑**：负责从复杂的自然语言中理解多房号纠错（谁是作废房号、谁是最终有效房号），并在复合情绪冲突中根据优先级阶梯（客诉公关 P0 > 险情抢险 P1 > 常规服务 P2 > FAQ P3）裁决主意图；
2. **状态机合规沙盒**：负责底层资产、数据安全与强类型校验（PMS在住校验、3~4位纯数字强校验、跨房拦截、早餐券配额卡死、工单状态闭环流转）；
3. **高并发压测基线**：提供全异步并发压测工具，验证 50+ 并发住客下的 QPS、延迟与零数据串流。

## 2. 详细功能规范

### 2.1 房号语义提取与沙盒校验 (`hotel_core.py`)
1. **大模型提取规范 (`ReceptionAgent.understand`)**：
   在 JSON 提取 Prompt 中新增 `room_no` 字段定义：
   > `提取 JSON：intent, sentiment, room_no(住客的有效房间号，纯数字字符串或null)。`
   > `特别注意：若住客存在口误纠错、更正、换房或提到多个房号（如'我是1102……不对我记错了，其实我是1106'），请理解上下文逻辑，提取住客最终明确认定的当前有效房间号（仅提取纯数字，若未确定则为null）。`
2. **代码级沙盒质检 (`understand`)**：
   - 若大模型提取出 `cloud_room`：
     - 使用正则 `re.fullmatch(r"\d{3,4}", str(cloud_room))` 校验格式；
     - 检查该房号是否在当前 `pms_rooms` 字典中；
     - 校验通过后方可作为合法房号采纳。
3. **离线/规则保底 (`_room_no`)**：
   - 增加强纠错优先匹配：
     `corr_pattern = r"(?:不对|记错|搞错|其实是|更正|纠正|换成|改为|变成)\D*?(\d{3,4})(?!\d)"`
   - 避免早期正则 `|是|` 贪婪抢先截获被废弃的旧房号。

---

### 2.2 复合冲突客诉与大堂经理优先级抢占 (`hotel_core.py`)
1. **意图阶梯 Prompt 明确化**：
   在 `understand` Prompt 中注入裁决阶梯：
   > `意图判定优先级（P0最高）：`
   > `P0 客诉紧急：住客表达强烈不满、指责服务卫生（如'臭死了'、'怎么做卫生的'）、或明确要求管理层介入（如'让大堂经理给我解释'、'找经理'）。即便同时提到修东西或问问题，主意图必须锁定为【客诉紧急】！`
   > `P1 工程报修：漏水、水管爆、设备故障；`
   > `P2 送物 / 续住申请 / 票券服务；`
   > `P3 酒店咨询 / 闲聊。`
2. **移除规则越权阻碍**：
   在 `understand` 中，**彻底移除**阻碍客诉升级的排他逻辑（原代码 `if result.get("intent") not in {"工程报修", "送物", "延迟退房"}: result["intent"] = "客诉紧急"`）：
   - 只要大模型判定为 `客诉紧急` 或住客明确要求大堂经理介入，坚决升级为 `ManagerEscalationAgent` 接管并标记红色高危工单，绝不被工程部分流！

---

### 2.3 重大险情与客诉静默设施介绍 FAQ (`hotel_core.py`)
在 `handle_request` 组装最终回复时：
- 若最终意图是 `工程报修`（且包含漏水、水管爆裂、断电等重大险情）或 `客诉紧急`：
  - 抑制普通的设施介绍类 FAQ（如 `shower` 淋浴花洒设施介绍），避免客人焦急求救时系统还在推销客房配有独立淋浴；
  - 全力输出安全避险自救与派单安抚。

---

### 2.4 异步高并发压力测试工具 (`tests/stress_test.py`)
编写自动化并发压测脚本，针对 FastAPI 服务（`http://127.0.0.1:8000`）：
1. 模拟 50 个并发独立 session（`stress_user_001` ~ `stress_user_050`）；
2. 每个 session 发起独立的业务调用；
3. 输出指标：
   - 成功率 (HTTP 200 比例)
   - 总耗时与 QPS (吞吐量)
   - 平均延迟、P95 / P99 延迟
   - 会话隔离性审计（验证 50 个会话之间是否存在数据交叉污染，串流数必须为 0）。
