# 用户实测反馈修复计划

背景：用户实测发现夜间连接按钮低对比、历史按小页替换、复合未知物品漏检、档案查询与多设施问答不完整。本次延续已有 Streamlit/API 架构，按可复现缺陷修复，不改入住授权、不新增商品或未经酒店核验的服务事实。

## 交付与方法

1. `agent_protocol.py`：用“桶/盒/袋”等量词和无空格并列项复现物品漏检；未知项不得因同一片段出现已知物品而被跳过。整轮不扣库，不把复杂请求简化成送水。覆盖原句及至少 8 个变体，保留单物品合法口语和正常 FAQ。
2. `hotel_core.py`、`data/service_catalog.json`：身份/会员按已绑定档案和 profile 回答，不让闲聊模型索要会员卡号/联系方式；姓名争议后不自述仍是旧姓名。明确找人工时给前台引导，单独“1”先澄清而不补造业务。足浴/洗脚按未核验服务答复，多设施问题各有答复，不能只答健身房。不编造学校设施位置/时间。
3. `deployed_ui.py`、`app.py`：历史从替换小页改为累计加载，首次 60 条、每次再取至多 60 条；通过 message_id 去重，顺序稳定，刷新不丢已加载较早消息，回到最新保留已加载记录。两端凭证/会话/实例变化均清掉旧缓存。控件移出消息滚动区，保证入口可找到，保持一个输入区；具体布局由 UI 实现者在两断点检查。
4. 夜间主按钮的正文/span/p 都使用同一组前景背景变量；对比度至少 4.5:1，不能仅凭存在某条 CSS 判通过。浏览器读取实际按钮文字颜色并截图。
5. 自动验证先 RED 后 GREEN；原始回归 ID 保留，旧分页测试更新为新用户契约。补充实际模型合成联调、一次只读集成复核和完整离线证据；原始日志存 `.artifacts/`。不清空用户会话，不停止 PyCharm8501。

## 分工与验收

- 主代理：协议/对话事实/服务目录与业务测试、规格、真实模型联调、完整验收和发布。
- UI 子代理：只改 app.py、deployed_ui.py、tests/test_guest_history_ui.py、tests/test_visual_contract.py；单独验证新加载语义和 CSS，不启动/停止用户服务。
- 只读复核：最终只审业务差量、隐私边界、历史去重隔离及上述范围，不自行修改或再派代理。

历史自动验收：至少 160 条记录累计到首条，无重复、无遗漏；加载更早后新消息出现仍保留旧记录；回到最新仍可找到之前加载的首条；切换凭证不可沿用旧缓存。浏览器复核 1280×720、390×844 发送区可见。模型测试报告实际调用次数和工单/库存断言，固定离线分母不掺入付费模型样本。
