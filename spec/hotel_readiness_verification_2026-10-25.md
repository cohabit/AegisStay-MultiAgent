## 2. 实际模型链路，独立于离线分母

沿用已有硅基流动配置，模型为 `Qwen/Qwen2.5-7B-Instruct`；只读模型列表预检成功，选定模型存在。没有输出或提交密钥，也没有重置用户的 PyCharm 服务和原会话。

使用独立内存 `SessionManager` 和仓库合成台账顺序执行 **17 轮**；记录真实 `json_extract/chat` 返回、耗时、工单和库存，未替换模型输出。实际 **9 次 JSON 提取、2 次闲聊调用**均有返回，单次调用 **1.219～1.604 秒**；目录、安全称呼和批量取消的确定性分支不为凑数调用模型。这不是端到端 P95 或可用性 SLA。

| 输入/场景 | 实际结果与断言 |
| --- | --- |
| `1128 送2条毛巾` | 数量 2、预留 2；毛巾 24→22 |
| `我只是嘴上很急，先别给我安排额外服务` | 简短回应，无新增工单 |
| `水，两瓶，给我再来一下，不用催` | 矿泉水 2 瓶，36→34；“一下”不再当未知物品 |
| `全部都不要了` | 取消本人两单未派送送物，毛巾恢复 24、水恢复 36 |
| `酒店能提供按摩吗` | 明确尚未核验，记录主题需求，不创建预约或工单 |
| 范围外宇宙话题 | 简短回复并转回酒店服务，无业务写入；不把任意闲聊变成送物或客诉 |
| `走廊插座冒烟还漏电，我已经离远了` | 高优先级工程单，先给安全提示；明确风险不能被模型降级 |

## 3. 8 个独立住客与换客

新增测试入口：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m unittest tests.test_hotel_readiness
```

该模块 **14 个方法**已包含在 241 项完整运行中。`ConcurrentGuestApiTests` 使用 8 个不同在住身份、独立凭证和独立 API 客户端，经 Barrier 同时各申请 6 条毛巾；共享库存初值为 24。

- 8 个请求均完成；4 单各预留 6，另 4 单记录缺货协调而没有库存预留，不能当成已确认派送。
- 总预留恰 **24**，库存 **0**，没有负库存或超卖。
- 对其中一位成功预留者连续取消两次，库存恰恢复 **6**，其他住客工单前后相等。
- 用该住客凭证读取另一住客历史返回 **403**。
- 新入住生成新 `stay_id/session_id`，历史、称呼状态和需求计数为空；旧凭证返回 **401**。旧记录留档不等于自动删除或被新入住继承。

复现曾暴露固定三次提交尝试在这批竞争下失败，现改为与工作线程数有界关联，默认最多 9 次；不是无限重试。原有 Event 受控取消/替换、旧 worker 禁止提交、持久化故障回滚等回归继续通过。此处是单进程共享 API 的功能竞争测试，不是现场人数、吞吐量、分布式部署或跨设备浏览器认证验收。
