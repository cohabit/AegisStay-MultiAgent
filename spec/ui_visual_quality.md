# AegisStay 界面视觉与酒店空间仿真规格

本文件是当前版本的界面验收规格，覆盖主题对比度、住客入口、房态地图、物资卡片和酒店空间仿真。它补充主规格中的业务要求；旧的 [UI 交互专题](ui_and_interaction_spec.md) 与 [早期房态规划](hotel_simulation_spec.md) 只保留为历史背景，不能作为本版本的通过证据。

## 1. 目标与边界

工作台服务一所学校的单酒店。界面要让住客先对话，让值班人员一眼看懂房态、工单和物资；空间仿真只用于运营定位和演示当前合成 PMS 状态，不声称是建筑施工图，也不替代真实 PMS 或消防图纸。

## 2. 当前交付契约

### UI-01 主题和对比度

1. `日间`、`护眼`、`夜间` 三套主题必须通过同一组 CSS 变量驱动背景、卡片、正文、辅助文字、边框和主色。
2. 每套主题的正常正文和辅助文字相对页面背景的 WCAG 2.1 对比度均不低于 **4.5:1**；主按钮文字与主按钮背景不低于 **4.5:1**。大字号标题最低 **3:1**。
3. 侧栏标题、说明、单选项、折叠面板和禁用按钮必须显式继承主题颜色，不能出现深色背景配深色字或白色按钮配近白字。禁用只降低操作能力，不降低可读性。
4. 占位文字、Tab 未选中/选中状态、错误/成功提示和房态图例也必须使用主题变量或有明确对比度的固定颜色。

### UI-02 住客端与工作区隔离

1. 默认工作区是 `住客端`，只渲染住客对话；房态矩阵、库存、酒店仿真、内部黑板和 Agent Trace 不得出现在住客端页面结构中。
2. 侧栏工作区至少包含 `住客端`、`运营中枢`、`质量验收`、`难例回归` 四项；只有切换到相应工作区后才加载对应内容。
3. 住客端可见消息输入框只出现 **1 个**。内部黑板放在运营中枢的折叠区域，不能作为住客页签展示。
4. 首次加载进入空状态：输入框居中、无具体房号示例；提交首条消息后，历史记录面板放大，输入框移动到面板下方并播放一次过渡动画。
5. 页面必须明确提示入住凭证绑定范围：住客不能通过聊天切换到其他房间。部署模式使用服务端凭证绑定；本地演示模式首次补槽只用于验证演示房间。

### UI-03 房态矩阵

1. 宽桌面端每层固定 **6 列**，每个房间卡片尺寸一致；筛选后不足 6 个房间时用无交互的虚线占位格补齐末行。
2. 中等视口（801–1100px）切换为 3 列，小屏（不超过 800px）切换为 2 列，不能产生横向滚动；卡片悬停或键盘聚焦显示房号、房态、住客、库存、退房和工单数。
3. 房态颜色必须同时有文字和图例，不得仅靠颜色区分：在住、空净房、待清洁、维修中四种状态都必须可读。

### UI-04 物资卡片

物资按布草、客耗、借用设备、餐饮分组，以卡片展示数量、单位、库存健康度和进行中预留；不得把原始 Python 字典或 JSON 作为主要运营界面。库存为 0、低库存和充足三种状态必须有文字标签。

### UI-05 酒店空间仿真

运营中枢在房态矩阵之前展示全楼概览；选择具体楼层后再展示单层平面图，至少包含：

- 左右两侧客房区，房间号与当前 PMS 房态同步；
- 两部电梯、一个安全楼梯和一个布草/服务核心；
- 建筑照片或稳定的占位背景、楼层标题和四种房态图例；
- 悬停房间能看到房态，存在处理中工单时显示工单提示。

默认概览必须包含所有可用楼层（包括 11F VIP），不能把 8F 作为唯一楼层。仿真图不写入业务状态，不新增第二份房态数据；切换楼层或筛选条件后，图和矩阵读取同一个 `pms_rooms` 快照。

### UI-06 住客端聚焦对话与运营端克制布局

1. 住客端首屏使用校园实景作为低对比度背景：图片必须经过至少 **12px** 的视觉虚化或等效半透明遮罩，正文与输入卡片仍使用主题变量，不能让照片压过文字。
2. 住客端不得依靠整页纵向延长来承载聊天。活动会话必须使用 `client-history-panel` 固定高度容器，默认高度 **300px**（小屏不超过 `calc(100vh - 300px)`），历史消息在容器内部滚动；页面主体在 720px 高视口内不产生第二个聊天滚动区。
3. 提交首条消息后，历史面板、输入框和异步处理中提示必须同时可见；处理中提示只出现一处，输入框仍可提交补充、修改或取消，不因后台 Agent 未完成而冻结页面。
4. 运营中枢、质量验收和难例回归使用紧凑的 `workspace-header`，不加载住客端校园大图或入口/客房照片条。运营端的图片仅在确实解释房态、楼层或设备时使用；装饰图不得占据首屏主要高度。
5. 空状态和活动状态均要用浏览器截图复核：空状态不超过首屏高度，活动状态的消息列表高度固定且在列表内出现滚动条；截图中不得出现空白大面板遮住输入框或工单状态。

## 3. 可复现实验与量化判定

### ENV-UI

```powershell
$py = (Resolve-Path '.venv\Scripts\python.exe').Path
& $py -B -X utf8 -m unittest -v tests.test_visual_contract tests.test_streamlit
```

机器判定必须同时满足：

| 检查 | 门槛 | 失败判定 |
| --- | --- | --- |
| 主题颜色 | 3 套主题各自 `text/bg >= 4.5`、`muted/bg >= 4.5`、`accent_text/accent >= 4.5` | 任一主题或任一字段低于门槛 |
| 页面结构 | 默认工作区为住客端，住客端只含 1 个可见 composer；运营内容通过工作区选择器进入 | 客户端出现房态/库存/仿真/内部黑板，或两个可见输入框 |
| 对话生命周期 | 空状态与 active 状态均可渲染；活动历史面板固定为 300px（小屏按视口收缩），输入框位于其下方且处理中提示只出现 1 处 | 首条消息显示延迟、历史被挤在页面底部、出现两个滚动区或无绑定范围提示 |
| 房态布局 | 源码包含 `repeat(6, minmax(0, 1fr))`、占位格标记、801–1100px 三列和小屏两列 | 自动列数、缺少占位格或横向溢出 |
| 空间仿真 | 同一渲染路径含 `.hotel-building-overview`、全楼层行、房间、电梯、楼梯、服务核心 | 只显示 8F、数字/JSON，或仿真状态不来自 PMS |
| 回归 | `tests.test_visual_contract` 与 `tests.test_streamlit` 零失败、零错误、零跳过 | 只看 HTTP 200、截图或进程退出码，不读取 unittest 结果 |

人工复核至少截取四张图：护眼住客端空状态首屏、住客端活动对话首屏、夜间住客端首屏、无装饰大图的运营中枢房态与仿真图；截图不得包含 API Key、真实住客资料或调试 JSON。截图是布局证据，不能替代颜色计算和自动测试。

## 4. 交付和边界

代码实现位于 `app.py`；颜色门槛由 `tests/test_visual_contract.py` 计算。界面通过不等于真实学校酒店现场验收，真实 PMS、SSO、建筑尺寸、消防设施和现场无障碍仍按 FIELD 方案单独验证。
